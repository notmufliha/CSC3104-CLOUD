# ScamGuard web app

A replica of the iOS app (`ios-app/`) in a browser: the same screens, flow, wording, colours and sizes, in Standard
and Simple mode, at all three privacy levels. Static files, no build step: open it from the compose edge at
**http://127.0.0.1:8088/** (or `http://<laptop IP>:8088/` from a phone on the same Wi-Fi / hotspot), or from the
Kubernetes Ingress at `https://<laptop IP>:8443/`.

- **Computer (wider than 600 px):** the app sits in a generic phone frame; "Show phone frame" and the light / dark
  switch are above it.
- **Phone:** no frame, full screen. "Add to Home Screen" opens it like an app (web app manifest + icons).

## What it does (same as the iOS app)

First-launch setup ("Who will use this phone?": Me / Me, but simpler / An older family member), Standard and Simple
mode, the guided tours, App style switching (leaving Simple asks for the PIN), Home, the script picker (the
learning-loop test calls only in the Developer view), incoming call, in-call screen (risk bar, chips, chat), the
"Be careful" banner, the full-screen red warning (sound, vibration where the browser has it, read aloud with the
Web Speech API), the summary with "What to do now", Dashboard, Insights, History and call detail with the same
charts, Learn (scam types + practice quiz), the family weekly summary (Web Share, else Copy text), Settings (privacy
level, family contact, text size, read aloud, My data, Help & about) and the hidden Developer view (tap the version 7
times: server address, models and model updates, the last call's table, the masked request log, live score overlay,
playback speed, sample history, reset to first launch).

- **Cloud:** every caller line goes to the gateway (`api/v1/utterance`, `api/v1/call/end` with the 3 s end-of-call wait).
- **Hybrid and On-device:** the three small English models run in the browser (`js/ondevice/`: the workers' text
  cleaning incl. Python's regex behaviour, TF-IDF / hashing linear models with MurmurHash3, the aggregator's rules).
  Hybrid sends only the caller's last 5 lines, masked, to `api/v1/verify`; On-device sends nothing.
- History, labels and downloaded models are in IndexedDB; settings in localStorage; the PIN only as a salted
  PBKDF2-SHA256 hash (the same hash as the apps). Nothing new is uploaded.

## What differs from the iOS app (and why)

- Calls and texts are `tel:` / `sms:` links: on a phone they open the Phone / Messages app; on a computer the app says
  what would happen ("On a phone this would call 1799").
- No MobileBERT: the 26.6 MB model plus the ~10 MB onnxruntime-web WebAssembly would have to be vendored into `web/`.
  Level 3 uses the three small models only (shown in the Developer view).
- The weekly reminder is a browser notification shown while the page is open (Sunday after 10 am) and needs HTTPS or
  localhost; it can't wake a closed page.
- On plain `http://<IP>:8088/` (not a secure context) browsers turn off the clipboard API, Web Share and
  notifications: "Share" becomes "Copy text" (copied the old way), and the PIN is hashed in JavaScript (same result).
- Fonts and icons: the system font (SF Pro on Apple devices); Lucide icons stand in for SF Symbols. "Largest" text is
  the app's own Extra large setting (a browser can't read the phone's Dynamic Type size).
- "How to block this number" shows the iPhone steps.

## Layout

```
index.html, manifest.webmanifest, css/app.css   page, PWA manifest, the iOS look (Theme colours, text styles, components)
js/main.js                                      start-up and the demo launch options (?demo...)
js/vm.js                                        the view model (port of UI/CallViewModel.swift)
js/logic/      risk, reasons, warnings, masking, onboarding, PIN, dashboard stats, weekly summary, quiz, developer
js/ondevice/   Python-regex port, text cleaning, linear models, MurmurHash3, LocalRules, OnDeviceCall
js/data/       settings (localStorage), history (IndexedDB), gateway client and model updates
js/ui/         screens and components (Preact + htm), charts (SVG), the phone frame, the tour
vendor/        Preact + hooks + htm (one ES module), licences      icons/  app icons
assets/        strings.json, learn.json (generated by tools/i18n, tools/learn), scripts/, models/ (copied by tools/)
tests/         Node unit tests; tests/e2e/ Playwright end-to-end tests and the iOS comparison
Dockerfile, nginx.conf                          the scam/web image for Kubernetes (demo/up.sh builds it)
```

## Maintenance

```bash
cd web
npm install                  # dev tools only (Preact/htm and Lucide sources, Playwright for the tests)
npm run vendor               # re-copy vendor/preact-htm.js and js/ui/icons.js
npm run sync                 # re-copy assets/scripts and assets/models from the iOS app
python3 ../tools/i18n/gen_strings.py && python3 ../tools/learn/build_learn.py   # wording and Learn content
npm test                     # unit tests (Node): parity (317 sentences), LocalRules, masking, PIN, onboarding, weekly...
npm run e2e                  # end-to-end in Chromium against docker compose (setup paths, calls at all 3 levels, quiz...)
npm run compare              # iOS Simulator vs web screenshots -> build/compare/index.html
```
